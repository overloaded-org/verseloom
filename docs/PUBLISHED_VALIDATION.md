# 正式发布包的移动端和算法复验

本切片保留主分支685e34a的手机适配、joint-lines.v4及corpus-lattice.v1.1，不用并行本地草案覆盖已提交生成器。新增独立的 `Published mobile and algorithm validation` 工作流：对每次成功的main Pages发布，下载同一个github-pages构件并进行实际浏览器与算法复验；也可手动运行，验证最近一次成功发布。

## 身份与安全边界

先核对仓库、来源分支、push/手动事件、Pages工作流路径和成功状态；拒绝fork/PR、过期构件、非预期文件布局及路径穿越。下载ZIP必须匹配GitHub提供的SHA-256，解包拒绝链接/特殊文件，逐项核对站点manifest中的字节与SHA，release.commit必须与源run的head_sha一致。未通过这些检查不执行构件JavaScript。

检验代码提交和被检验的发布提交可能不同：纯测试提交不会假称已改变线上程序。`identity.json`明确记录sourceCommit/sourceRun/artifactDigest，测试所用脚本则来自本次检验工作流提交。

## 移动端检验

复用仓库已有 `tests_mobile/check_mobile.py`，Playwright固定1.57.0。实际Chromium加载打包HTML、样式及生成代码；四个入口、五/七言、320/375/390/430/768px共40组。点击生成、展开长证据，核对无横向溢出、窄屏控件高度；自组织使用实际Blob Worker并检查种子复现。报告记录实际浏览器版本、脚本错误和全部布局测量。

页面通过内存加载，不访问用户浏览器或账户，不把这种测试称为正式URL按钮测试或iOS Safari真机验证。正式URL字节验证仍由原Pages的verify-live执行。

## 算法研究没有停止

从同一个发布包运行两种检验：

- 基线五言、七言，各取种子0..63，探索0.8、宽度32、不带历史。记录全部128次结果和两个用户指出词段的出现首数；不把这两个词传给生成器，不要求结果必须为零。
- 语料自组织五言、七言，各取种子0..7、宽度16，对比local与relations，共32次。每组必须拥有相同候选池指纹；记录是否成篇、输出是否改变。验证未读取人工内容词表/句法框架的声明，保留所有无解；不强制跨句评分一定换稿。

词表与接续由原训练语料学习；没有增加故事路线、必须出现的人物或替换诗句。相关图依然是统计关联，不是事件因果。字书候选、严格对仗、文学质量仍不由此次检查认证，独立文学评分为0。

上一轮曾在相同8b77008基线上制作另一套本地避重草案，得到2/64的观察数；该草案未进入main。正式版本数字以当前发布包probe为准，不能将两套实现的样本混为一次实验。

工作流成功、实际计数和浏览器版本均以Actions产物为准，不预写成功状态。完整产物包括40组布局、截图、128次重复诊断、32次未改写诗稿及配对结果。
