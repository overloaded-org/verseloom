# SP-02：中联联合搜索 × 整诗迭代修订

本轮不再只增加审计字段：两条可执行搜索路线已实现，并使用相同程序初稿进行并行对照。基线源码为 `c9c8127c81d4067699adba95668dd6776740ed9e`，未更改训练语料、人工内容词表、字书读音或线上默认行为。

## 实现

- **联合搜索**：颔联、颈联的上下句作为一个原子修改，评价完整两句后再选择，不在上句阶段提前剪枝。另有固定其余六句的中联/尾联局部对照。
- **迭代修订**：最多四轮重新访问全部八句；首句、颔联、颈联与结尾都可以改。每次重算整诗和所有受影响的后续关系分，只有整诗目标严格增加才接受。保留每次提议计数、修改行、改前改后文本和分数。
- 四臂：逐句一轮、联合中联一轮、逐句迭代、联合中联迭代。联合路线的首尾联也开放修改，但主实验仍逐句更新首尾联；尾联原子替换另有明确的局部实验，不冒称四联全部联合生成。

研究入口复用现有词段搜索。`web/induced-engine.js` 只增加 Node/CommonJS 的 detached lattice 导出，不修改浏览器 `VerseLoomInduced` API 或原生成函数。返回深拷贝，研究工具不能改写生产候选缓存。不存在人工题材、人物配额、词性框架、必选句或投诉词黑名单。

初稿由原引擎自行生成，再固定它自动选出的韵部和起式以隔离干预。局部对照冻结的六句也来自同一程序初稿，仅作为实验控制；产品没有“必须输出这六句”的入口。

## 不是扩散模型

本轮是**有限候选域上的块坐标优化**。它既没有训练逐步噪声过程，也没有训练反向去噪分布；不能因多轮改稿便称为离散扩散。真正的离散扩散与掩码预测分别需要其训练目标和条件分布，参见 [D3PM](https://arxiv.org/abs/2107.03006) 与 [MaskGIT](https://openaccess.thecvf.com/content/CVPR2022/html/Chang_MaskGIT_Masked_Generative_Image_Transformer_CVPR_2022_paper.html)。本代码不是这两项工作的复现，也不借用其效果结论。

## 事先固定的协议

见 `research/parallel-refinement-v1.json`。五言/七言各取种子 `[0,1,2,3,42,43,44,45]`；初稿用 learned、variation=0.8、beam=16、空历史。每个句位最多24个运行时生成候选，保留原程序候选以允许“不改”，不填入新的人写句子。

每臂提议上限4096，最多四轮。**共同预算上限不等于相同实际计算量。** 逐句优化较早收敛，联合枚举通常花费更多计算；完整报告同时公布实际提议数，不据此宣称算力效率或同算力文学优势。修改阶段不再注入随机扰动，只优化固定 learned 整诗分；初始候选仍由种子确定。

这些种子已经用于开发，不能算新的盲测。目标分同时被优化与测量，分数提高不证明诗更通顺。

## 本地实测

16个程序初稿全部成篇。四臂共64份修订输出；另做3个局部位置（第3–4、5–6、7–8句）×16初稿×2算法，共96份输出。合计160份修订/局部结果，连同16份原初稿全部保留。

| 诗体 | 逐句一轮平均增分 | 中联联合一轮 | 逐句迭代 | 中联联合迭代 |
|---|---:|---:|---:|---:|
| 五言 | 3.5409 | 3.7338 | 3.7890 | 3.8235 |
| 七言 | 3.8590 | 3.9747 | 4.1422 | 4.2303 |

单位为当前内部整诗目标增量，不是文学评分。

固定上下文的48组局部对照中，联合搜索14组更高、34组持平、0组更低。其中中间两联为11/32组更高，尾联为3/16组更高。联合搜索穷举了同一有限双句网格，搜索空间包含逐句结果，因此“不劣”本身并不是独立质量证据。

联合迭代相比联合一轮，12/16份目标继续提升、4份持平；没有任何句位永久锁定。联合迭代相比逐句迭代为7组更高、7组持平、**2组更低**。分轮的局部选择可进入不同解，不能声称联合方法总是更好。七言seed45的联合迭代用完4096次提议，保留了预算耗尽状态。

实际平均提议数：五言逐句迭代557.25、联合迭代2862；七言逐句迭代552、联合迭代3632。联合路线明显更贵，需要继续做质量/成本比较。

## 反证样本：第一种子，不挑佳作

五言seed0联合迭代原样输出包含：

> 水垂青靄遠，別有一條寒。

七言seed0联合迭代原样输出开头为：

> 同清話昔年曾到，天欲明歡喜見來。

内部目标虽然提高，这些句子仍存在明显的句意或句法问题。本轮自查不能冒充独立文学评审；它恰好说明旧评分器仍会奖励不通顺组合。不能通过给这几个具体词加黑名单修饰数字，更不能手工改字后当作算法输出。

## 验证

17项Node测试通过，覆盖原子双句跨越单句合法性障碍、有限网格穷举oracle、预算含非法提议、迭代重新访问首句、局部上下文不变、单调轨迹、复现、无解无兜底、恶意候选注入、来源一致性、Node/浏览器接口隔离和候选缓存不被研究改写。

独立Python实现重算词段条件概率、全部8项关系特征、训练系数、平仄与押韵、重字限制和来源候选：**160份输出、7680个字位、875个轨迹块通过**，其中424次接受修改。每次接受都重算完整目标，没有绕开相应后续行。共重算240个不同状态。词项来源仍对应训练统计；没有做新的古音专家认证。

首轮测试发现的失败是测试比较单边JSON序列化导致 `-0/0` 不一致，修复测试为双边同一序列化后17/17通过；未修改模型或择句以迎合测试。独立算术审计对未序列化数学值仍使用明确容差。

本地运行环境Node22.16.0/Python3.13.5；新增CI用Node24/Python3.12从固定来源重建。远端是否成功应以Actions结果为准，不能把此处本地结果预写为远端成功。

## 复现

按现有脚本构建数据后：

```sh
python scripts/bootstrap_quality_data.py --download --cache output/source/cache --output output/source/run
python scripts/build_induced_model.py --bootstrap output/source
node --test tests_refinement/*.test.cjs
node scripts/run_parallel_refinement.cjs output/parallel-v1
python scripts/audit_parallel_refinement.py --run output/parallel-v1 --output output/parallel-v1/audit.json
```

运行器同时启动五言/七言，等待两个进程结束，保留失败状态；已有结果目录拒绝覆盖。协议、输入SHA、原样初稿、四臂输出、全部修改轨迹、局部干预和统计报告均保存。`docs/PARALLEL_REFINEMENT_V1_RESULT.json`为本地数值摘要。

## 决策

**搜索实现完成，Research GO；Production STOP。** 本轮没有替换Pages默认算法。下一瓶颈已经清楚：评分器无法可靠判断一句是否通顺，即使更完整地搜索，也可能更有效地优化错误目标。真正的下一步是训练并验证可识别句法/语篇破坏的条件模型或去噪目标，而不是继续加大迭代次数就宣称诗更好。
