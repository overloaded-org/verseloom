# 八句共同搜索：joint-lines.v3

本说明替代旧版“先抽首句，再续写”的设计。只保留格律及既有机械约束，不接受任何必选诗句或首句锚点。

## 实际变化

- 删除 `selectOpening`、单候选首句池和失败后换锚点重试。
- 每行对全部合资格候选评分；探索模式保留不同起首词块的路径并行续写，所有路径共用同一个 beam 预算。组内和组间按已累计的探索分排序、轮流保留，避免单一开头提前占满搜索宽度。
- 八句完成后，才在完整路径之间进行种子驱动选择。按首二字分组避免重复候选数量本身增加抽中机会；组权重取组内最高完整诗探索分的每句均值，组内路径同样按每句均值 softmax 抽取。温度等于探索强度。此分布只覆盖保留的完整路径，不是全体诗的概率分布。
- 随机扰动作用于全部八个句位；同版本、同数据、同种子、同参数及历史可复现。探索强度为 0 时保留历史确定性搜索，不从存档读取诗句。
- 最近首句历史只排除近期重复，不指定必选句。保留手动种子、关闭近期去重及精确重放入口；历史仅记录本页实际成功输出。
- 初始页面为空白，不显示预写诗稿；“恢复自由探索”不会关闭随机或强制恢复首作。

`opening` 为 null。`selection.stage` 为 `after-eight-lines`，`provenance.preselectedLines` 为 false。逐行记录候选数量、保留首句数和起首词块数，可检查是否过早合并分支。宽度 1 自然只能保留一条路径，但不预先指定句子；网页提供 16/32/64。

## 本地核验（2026-10-30）

27 项 Node 引擎和 DOM 合约测试通过。包含历史路径一致性、全部 48 个起式×韵部组合及近期历史、多种子、取消、Worker 一致性、参数检查、空白启动和实际 UI 事件调用。DOM 合约不等于 Chrome/Safari 真实排版兼容测试。

固定仄起首句不入韵、下平一先、搜索宽度 32、探索强度 0.8、无历史，种子 0..63：

- 64 个不同的全诗输出；首句 44 种；起首二字 30 种，最高出现 5/64 次。
- 八个句位的不同整句数分别为 44、26、36、30、34、28、31、33。
- 这些是指定样本的描述统计，不保证任意种子绝不重复，也不证明文学质量提升。

## 尚存边界

网页仍在冻结的 2,392 个、由语料片段组成并已评分的候选句内搜索；这次解除的是“预定输出句”和“首句锚定”，没有把有限候选检索改称无限自由造句。候选集、基本声律模板、统计模型没有重新训练。历史诗稿仍在数据中作为回归核验基准，但生成器不读取它来决定输出。

语境读音、严格对仗、文学质量、全语料原创性及全局最优仍不作保证。不得用人工改写的句子替代程序输出，或把未找到解时返回的存档当作生成成功。
