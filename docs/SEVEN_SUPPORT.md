# 五言／七言网页生成

新增“诗体”选项。五言为八句四十字，七言为八句五十六字。两种诗体共用 `web/engine.js` 的 joint-lines.v3 无锚点搜索：八句完成后才选择完整路径，随机探索覆盖所有句位。未加入任何预写首句、指定中间句或失败时的存档替代。

## 七言数据

`python scripts/build_web_seven.py` 从现有固定 `train` 分割的 299 首七言形状文本构建 4+3 片段组合。它们不是逐首认证的严格律诗金标。开发集和测试集在 JSON 解码前跳过。五言原始数据、语料分割、韵表、历史源码和原试验记录不变。

七言材料较少，片段计数门槛明确设为至少一次；五言保留至少两次。每个保留片段随数据附带原诗 ID、行号和截取范围。剔除未知字、参考表跨平仄字、已标记校勘问题字、句内重字以及七言训练集完整原句。语境读音没有据此得到认证。

构建对 308,697 个合资格组合评分，保留 3,892 个七字候选句。按韵脚覆盖得到 18 个可选韵部。两种诗体各有四种基本模板；七言采用严格基本平仄，不声称覆盖所有变格与拗救。基础规则另可参见维基文库《律詩定體》：https://zh.wikisource.org/zh/律詩定體 。

浏览器实时执行整诗约束搜索，4+3 词块组合及统计语言分预先计算。并不是开放字词空间生成，也没有调用大模型或训练新的卷积模型。

## 复现及页面

同数据、同诗体、同种子、同参数和同历史可复现。返回结果增加 `lineLength`，可从 JSON 审核。五言／七言分别保存本页最近成功首句；切换诗体重置对应韵部、起式和显示区，不把五字历史传入七言。手动种子及复现不消耗新的随机数。页面初始为空。

七言查看片段时显示“前四字＋后三字”，平仄渲染包含七个字，韵脚位于第七字。Worker 与单文件主线程使用同一引擎。离线构建内联两套数据与附加样式。

## 本轮实测

固定 `L7-P-R0`、自动选定的上平四支、宽度 32、强度 0.8、无历史，种子 0..63：64 个不同全诗；八个句位的不同句数为 36、32、40、31、38、30、27、37。这是指定样本的描述结果，不保证不同种子绝不重复，也不是文学质量评价。

新增七言与诗体切换共 9 项 Node 测试：包含 72 个起式×韵部组合各自有无历史两次生成、独立字音韵脚核对、来源查验、64 种子、Worker、取消、输入拒绝、五言冻结回归及实际 UI 事件逻辑。DOM 测试不等于真实浏览器渲染测试。既有 175 项 Python 测试通过。

```sh
python scripts/build_web_data.py
python scripts/build_web_seven.py
python scripts/build_web_seven.py --check
node --test tests_web/seven.test.cjs tests_web/form-ui.test.cjs
python scripts/build_web_demo.py --output _site
```

Pages 工作流保留既有 27 项网页检查，再运行新增检查；发布后下载线上数据和引擎，按本次构建 SHA 验证七言生成与种子复现。真实远端状态以 Actions 记录为准。

文学质量、严格对仗、语境读音、全语料原创性及全局最优仍未认证。七言候选表的来源与派生数据许可沿用已有 NOTICE。
