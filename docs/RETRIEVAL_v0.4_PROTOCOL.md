# v0.4：固定输出池大小的二字片段检索确认

本轮研究原文二字片段能否进入有限候选池。v0.3 的模型和已暴露测试结果保留；不重训或重新选择 CNN，不把本轮召回率视为复原准确率、形式对仗或文学质量。

## 1. 冻结范围

运行配置见 `configs/retrieval_v0.4.json`。`scripts/run_retrieval_v04.py dev` 在读取并排序开发题之前，保存代码、配置、旧训练/开发文件、独立确认语料文件的 SHA。确认文件此时只按字节校验，不解析题面或目标。确认语料的构建政策、源码和全部旧排除文本，在下载固定新分片之前已另行冻结。

这是本地运行前冻结，不是外部预注册。确认结果产生后，数据状态立即变为已暴露；后续改动不能继续用它作新的独立确认。

## 2. 训练与可见输入

只使用 v0.3 的 2,502 首 train 文本，保持已有字符表与 UNK。旧 test 记录在检索运行器中于 JSON 解码前跳过；旧全部文本可被独立语料构建器用来排除新旧诗族重叠。

公开查询类型仍是 `VisibleQuery(length, upper_line, lower_suffix, start=0, mask_length=2)`。不得传入 target、完整下句、作者、题名。目标仅在完整评分向量返回后用于计算排名。

“词”在此指连续二字片段，不主张已完成古汉语分词。原 Unicode 字形保持不变。未知题面字显式映射 UNK；新增片段关联按原始字面统计，避免不同未知字被错误合为一个关联事件。

## 3. 候选来源与方法

窄词表 N 是原 v0.3 训练下句首二字、频次至少 2，五言 1,317 项、七言 97 项。宽词表 W 收集全部训练诗句内的相邻二字、频次至少 2，五言 10,375 项、七言 1,504 项。不同句长分开计数；不跨句拼接、不注入开发或确认目标。

原统计分数 S 保持 `BidirNGram` 的双向字符插值及上下对应字统计。加速版必须复现原分数与排名；不量化分数、不更改同分词典序。

两个附加项都按句长独立计数：

- A：对每联上下句的所有对齐相邻二字位置，计数“上片段、下片段”的共同出现。查询上下文为上句首二字。
- B：对所有训练句内四字窗口，计数“前二字片段、后二字上下文”的共同出现。查询上下文为可见下句后缀的首二字。

两种事件均只保留下片段/前片段属于 W 的事件。令 `p(w)=(count_all_adjacent(w)+0.1)/(sum_eligible_counts+0.1*|W|)`，两个附加分均为 `log1p(joint_count/(5*p(w)))`。省略的条件归一化项在同一查询下对所有候选相同。这是用于排序的平滑关联加分，不是正确概率。

宽池评分为 `S + weight_A*A + weight_B*B`。每个权重取 `[0, 0.25, 0.5, 1]`，固定 16 个方案；A 为外层、B 为内层的嵌套顺序。`A=B=0` 是宽池原统计基线。

## 4. 开发选择

在旧 dev 的 547 首、2,188 题上公开全部 16 个方案及窄基线的结果。仅按诗族等权的 recall@16 选择一个宽池方案：族内全部题平均，再对诗族等权。选择使用精确有理数比较；完全同分保留网格顺序中的第一项。不得以 top1、其他 K、MRR、句长切片替换主选择指标。

开发运行还按 task_id 的 SHA 排序，每句长固定取前 8 题，对整个窄词表以原标量 `BidirNGram.score` 重算分数和完整排名。核对必须精确相等；失败即停止，不默默改定义。

选定方法、开发逐题结果、报告、候选来源、训练统计与确认题文件 SHA 写入独立的 `selection_frozen.json`。确认阶段从已校验的开发逐题结果重新计算选择，要求与选择记录和开发报告三者一致。

## 5. 新确认集

来源为 chinese-poetry/chinese-poetry 固定提交 `b8594f81a89752241442f2ce267d6f66f96704ee` 的唐诗分片 10000 至 19000，步长 1000。不得按结果增加、替换分片或改变样本量。

沿用 v0.3 的纯 CJK、八句五/七言形态规则。新文本精确去重后，与全部旧 3,579 首联合建图：全文相同、共享整句、句内二字组集合 Jaccard≥0.8 均连边，取传递连通分量。剔除所有含旧诗分量中的新诗，包括经其他新诗间接连接的情况。

对其余新诗族，按 `SHA256('versematrix-confirmation-v04-20261029' + ':' + family_id)` 排序，取前 512 族；族内全部诗保留。不足则全取，不另找来源补足。每首四联各出一题。实际构建得到 524 首、2,096 题、512 族。未选中的新文本只作为排除与选择证据，不进入训练/开发。

这一独立性限于指定表面关系；未证明穷尽异文关系，作者可跨集合，固定连续分片不是全体诗歌随机样本。八句形态筛选也不是严格律诗认证。

## 6. 确认评价与决策

确认只评价三项：窄池原统计、宽池原统计、开发集选中宽池方法。所有题、诗、诗族分母一致，词表外与前 K 外题都计零。

唯一确认性主比较：选中方法减窄池原统计的诗族等权 recall@16。对固定排序的诗族做 5,000 次配对 bootstrap，种子 2026102904，线性百分位 95% 区间。提升门要求点估计至少 +2 个百分点，且区间下界严格大于零。下界大于零不等于以 95% 置信度证明提升至少 2 个百分点。

以下属于次要/描述性分析，不改变主决策：宽池原统计减窄池原统计、选中方法减宽池原统计、recall@8/32/64、top1、全词表 MRR、五/七言切片。全词表 MRR 对词表外题记零。若 A、B 同时启用，只能支持选中组合，不能单独归因于一个附加项。

## 7. 计算成本

K=16 固定的是输出给后续重排器的池大小，未固定检索计算预算。宽池词表规模和排序候选数都更大。运行器在每题上共享一次宽池组件计算，再对各方法排序；因此各方法的 `ranked_candidates_per_task` 是逻辑排序量，不能充当分别测得的评分工作量或耗时。

报告同时保存共享组件查询数、宽池候选评分项数、每方法排序量和整阶段耗时。基线等价审计另列。开发 17 方法与确认 3 方法的整阶段耗时也不能直接当成单次在线调用延迟。
