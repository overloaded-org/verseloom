# v0.5 固定候选集的上下文—片段匹配开发实验

## 范围与固定判断

实际冻结预算为每模型1,200次更新、batch32，完整配置与源文件身份见 `results/matching_v05/freeze.json`。下文“草案预算”记录运行前的设计过程；正式实验未改变该预算。

本轮训练一个把可见上下文编码为查询向量、把二字片段编码为候选向量的模型。核心评分为 `Q Eᵀ / temperature`；W、K、原始训练/开发划分和统计强基线保持固定。正式评估只读取已经多次使用的开发集。本轮结果用于分配下一轮研究资源，不能称为独立确认或文学质量证据。

主实验在任何训练结果出现前指定为 `full_w3`。其他训练臂是机制对照；某个对照更好时，不得把它事后改称主实验成功。没有神经与统计评分插值，也没有混合权重网格。

## 数据与任务

使用 v0.3 的训练诗 2,502 首、开发诗 547 首，分别产生 10,008、2,188 道题。每题只遮住偶数句的前两个字；输入为同联上句全文与下句余下字符。`VisibleQuery` 白名单不含目标、作者、标题、原诗全文或任务身份。

旧 `test` 行在 JSON 解码前跳过。v0.4 确认语料不在本 runner 的输入路径中。对整个混合划分源文件计算 SHA 仅用于完整性校验，不代表解码或使用被跳过的旧测试文本。

W 只由训练文本全部八句内部的相邻二字构建，出现次数至少为 2，五言与七言独立计数：

| 句长 | W 大小 | 训练总题 | W 内训练正例 | 开发总题 | W 内开发目标 |
|---|---:|---:|---:|---:|---:|
| 五言 | 10,375 | 8,812 | 5,494 | 1,820 | 824 |
| 七言 | 1,504 | 1,196 | 457 | 368 | 73 |
| 合计 | 11,879（按句长计） | 10,008 | 5,951 | 2,188 | 897 |

训练只对目标存在于 W 的 5,951 题进行梯度更新。所有开发题仍然保留，包括 W 外的 1,291 题；W 外原文排名为缺失，R@16、top1 和 MRR 均计 0。不得向 W 注入开发目标，也不得因候选缺失删除开发题。

W 的来源位置与监督正例的位置不同。本轮不额外把其他位置的二字片段作为正例。候选资源逐项保存 `train_prefix_positive_count`，开发结果按下面三桶报告：

| 开发目标类别 | 题数 |
|---|---:|
| 在 W 内，训练中曾作为下句首二字正例 | 647 |
| 在 W 内，训练中从未作为下句首二字正例 | 250 |
| W 外 | 1,291 |

词表保留原 Unicode 字形，不做繁简、异体或读音合并。字符词表沿用原训练来源，包含显式且冻结的 UNK0；PAD 通过独立掩码处理。

## 模型与训练对照

字符嵌入维数 12，查询与候选表示维数 16；查询经过卷积、tanh 和按位置组织的投影，二字候选通过有序字符拼接与共享编码得到表示。二者使用平滑 L2 归一化，固定 `norm_epsilon=1e-6` 和温度 `0.1`。没有候选 ID 嵌入或每候选独立偏置。

| ID | 卷积宽度 | 通道数 | 可见上下文 | 角色 |
|---|---:|---:|---|---|
| `full_w3` | 3 | 24 | 上句与下句后缀 | 预先固定的主实验 |
| `full_w1` | 1 | 27 | 上句与下句后缀 | 卷积窗口为1的局部交互对照 |
| `upper_w3` | 3 | 24 | 仅上句 | 独立训练的信息对照 |
| `suffix_w3` | 3 | 24 | 仅下句后缀 | 独立训练的信息对照 |

宽度1只限定卷积层的局部窗口；后续固定位置投影仍读取全部可见位置。因此不能把这个对照称为完全不使用相邻字符或词序的模型。

上下句单独可见的训练臂关闭另一行，相关投影行冻结。每臂保存模型实际参数总数、可训练/冻结数量，不能仅用近似参数量宣称严格容量公平。

三个种子固定为 0、1、2。草案预算为每个模型 1,200 次优化更新、每次恰好 32 个训练任务，检查点为第 400、800、1,200 次更新。正式冻结前可以依据只读训练数据的工程吞吐预检确认预算；正式冻结后不能根据开发成绩增减更新次数。

优化器固定 Adam，学习率 0.003、解耦权重衰减 0.0001、全局梯度裁剪 5、β₁=0.9、β₂=0.999、ε=1e-8。每次 `train_step` 对固定句长 W 的全部候选计算完整 softmax 交叉熵；梯度累积为 1。一次更新与一次满 32 题批次一一对应。

句长批次数按 eligible 正例 5,494:457 的比例用最大余数法分配，然后按种子洗牌批次句长；每个句长有独立的无放回洗牌循环队列，跨循环补满 32。一个种子的四个臂共享完全相同的任务 ID 序列。每次、每检查点和每模型都记录实际曝光、独立任务、诗篇和诗族数，不把重复曝光当作新样本。

在 1,200 次更新的草案预算下，每模型曝光 38,400 次（五言 35,456、七言 2,944），会覆盖全部 5,951 个 eligible 任务，涉及 2,375 首诗、2,247 个诗族。12 个正式模型共 14,400 次优化更新、460,800 次曝光；训练吞吐预检与工程测试额外计算应另列，不属于新的独立实验。

## 固定基线

1. v0.4 统计强基线：完整 W，alignment weight=0.25，boundary weight=0.25，权重不再调节。
2. 无上下文的 W 片段频次：训练文本全部句内相邻二字计数，降序；同分按原文字典序。
3. 无上下文的首二字正例频次：训练偶数句前二字计数，W 内未作过此正例的片段计 0；同分按原文字典序。

K 固定为 16。主指标是：同题先对三个种子的 R@16 指示量取均值，再在诗族内平均，最后对诗族等权平均。题目微平均、top1、MRR、五/七言分层和三个正例状态桶是附加报告，不能替代主指标选检查点。

## 检查点选择

每个训练臂独立选择一个共同更新步数，由三个种子的上述主指标均值决定。使用有理数精确比较；完全同分时选较早检查点。同一臂的三个种子必须引用同一步数，不选择最佳种子，也不把多个种子当作额外独立题目。

模型保存为不可覆盖的 `models/{arm}_seed{seed}/update_0400.npz` 等文件。`selection_frozen.json` 只引用各文件路径和 SHA，不复制到容易被覆盖的 `selected.npz`。选择记录明确 `selection_scope=dev_only_not_independent_confirmation`。

每题都对完整 W 排名。保存原文排名、真实前 16 候选与原始分数、完整候选顺序和完整分数数组的 SHA；凭相同模型、W、可见查询和运行环境可复算全量顺序。排序规则固定为精确浮点分数降序，同分按原文字典序，不人为四舍五入制造同分。

## 上下文诊断

以下仅针对主臂共同选中的检查点及全部三个种子，不额外训练：

- `zero_context`：推理时使用 `mask="both"`，上下文全部隐藏。它属于冻结模型推理消融，不能混称为另外训练的无上下文模型。
- `mismatched_context`：保留原题目标和 W，将可见上句与后缀整体替换为另一题的可见查询。五言、七言分别按固定盐和任务 ID 的 SHA 排序，选第一个正循环偏移，使每一对原题/donor 都不同诗族、不同 `VisibleQuery` SHA。映射为同长一一置换，在训练及模型评分前冻结。

错配映射不读取目标，也不依据 donor 与原题的目标是否相同来过滤。改变目标必须不改变映射。逐题 donor 身份、可见查询摘要和错配后的排名均保存。

## 开发资源门

只有预先指定的 `full_w3` 可以触发下一轮独立确认的资源分配，且以下三个条件同时成立：

1. 主臂三种子均值的诗族等权 R@16，比固定统计强基线至少高 0.02。
2. 三个种子各自相对同一强基线的增益都严格大于 0。
3. 主臂真实上下文均值减去错配上下文均值至少为 0.01。

门使用精确有理数比较阈值，包括 `>=` 与 `>` 的区别。它是开发资源门，不是显著性检验，也不是新数据泛化证据。没有达到门时应保留失败结果，不能改阈值、挑有利种子、改主臂或继续沿用开发集作确认。

## 可复现补全入口

供 CLI 使用的候选模型固定为主臂 `full_w3` 的 seed 0，使用主臂共同选中的检查点。seed 0 在训练前固定，不是开发集最佳 seed，也不是三种子集成。

`deployment_candidate.json` 明确 `experimental`，记录模型路径/SHA、W 摘要和统计比较基线。该入口输出真实候选片段及成句，仅用于来源文本复原探索，不能标成格律认证或已验证文学创作能力。

## 执行与证据

```bash
python scripts/run_matching_v05.py prepare
python scripts/run_matching_v05.py run
```

`prepare` 必须在负责人确认草案后调用。它先将配置状态改为 `frozen`，冻结源代码与输入字节，再产生候选资源、覆盖统计、三种子固定采样序列和错配映射；不会进行任何正式参数更新或开发模型评分。`run` 校验全部冻结文件，完成每个声明的预算，最后选择检查点并输出报告。冻结后的源码、配置、数据或采样序列改变会中止；已有正式运行不允许静默覆盖或恢复。

主要证据为 `freeze.json`、`prepared.json`、`candidate_resources.json`、`coverage.json`、`schedules/`、`context_permutation.json`、`training/`、`checkpoints/`、`predictions/`、`baselines/`、`diagnostics/`、`selection_frozen.json`、`deployment_candidate.json` 和 `report.json`。
