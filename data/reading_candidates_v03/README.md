# 真实二字候选与音韵参考的关联审计

本目录把训练集二字候选逐字关联到现有106部原字形参考。**不选择语境读音，不生成已验证读音，不改变本轮模型候选池，也不作为训练特征。** 这一步连接两个已建数据层，不能视为格律金标门已经通过。

## 来源

- `../corpus_v03/candidate_spans.json`：只来自训练分割、最低出现2次的二字片段。
- `../reference_v02/pingshui_106_memberships.json`：原字形到全部候选字—部关系。
- `../reference_v02/editorial_issues.json`：此前已经标出的校勘议题。

脚本先核验上述文件与各自来源manifest中的SHA。`manifest.json`另保存本次所有输入、脚本及派生输出的SHA和字节数。既有语料及其冻结文件没有修改。

## 输出记录

`candidate_readings.jsonl`共1414条，对五言/七言分别保留片段身份。每条包含：句长、二字片段、训练计数、训练来源诗号、按位置排列的`character_records`、`requires_context_review=true`。

每字保留：

- 原始Unicode字符，零起位置。
- 所有来源成员记录，包含原有group_id、韵部名、tone、来源行号、status和可能的source_issue_ids；没有从中选一个。
- 整体tone_candidates，只表示这个参考允许的候选集合。
- 查不到时为`lookup_status=unknown`，成员数组为空。
- 字符相关的全部既有校勘议题，包括“正文缺字”导致成员数组为空的议题，如“啼”。

存在成员的记录保留`source_candidate_needs_context`；单一字—部候选或单一平仄候选，也始终需要语境复核。没有繁简转换、异体合并、猜读或自动改部。

## 实际审计

| 片段类别 | 五言 | 七言 |
|---|---:|---:|
| 总数 | 1317 | 97 |
| 两字均能查到 | 1250 | 92 |
| 两字各只有一个字—部候选 | 772 | 58 |
| 两字各只有一种平仄候选 | 935 | 72 |
| 至少一字有多个字—部候选 | 491 | 34 |
| 至少一字跨平仄 | 325 | 20 |
| 至少一字未知 | 67 | 5 |
| 至少一字关联已有校勘议题 | 5 | 0 |

**类别可以重叠，不能逐列相加当作分区。** 例如一字未知而另一字跨平仄，会同时计入两类。不同韵部也可能同为平声或同为仄声，因此“单一平仄”与“单一字—部候选”不等价。

五言片段中的已有校勘议题涉及“先”3次、“啼”2次。未知统计保留每字出现次数，见audit.json；“爲”“遊”等原字形未命中，未自动映射成其他字。未命中不意味着历史上没有该字或读音。

## 离线复核

```bash
python scripts/audit_candidate_readings_v03.py --check
```

脚本独立从输入字表重新计算类别数，并将每个输出成员数组与原参考逐条比较；`--check`再次构建所有输出并逐字节核对。没有读取测试预测。

## 许可与解释边界

来源数字录文的署名与许可继承 `../reference_v02/LICENSE_NOTICE.md`，诗文数字语料说明见 `../corpus_v03/LICENSE_NOTICE.md`；不能将这些第三方派生资料静默套用新增程序的许可。

本轮原文复原实验仍只评价与冻结文本的字面一致。此审计没有证实任何候选在指定诗句中的声调、韵部、对仗或文学质量。
